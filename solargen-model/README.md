# SolarGen Model

> Part of the [SolarGen](../README.md) project — see the root README for the full architecture overview.

FastAPI service responsible for predicting hourly solar production across all 21 sites of the Bundoora campus. Predictions are generated by a LightGBM model trained on the UNISOLAR dataset, using live weather data as input.

Unlike solargen-backend, which persists predictions to MySQL and serves historical data, this service is stateless. It holds no database, and every request triggers a fresh inference directly from the model. This keeps the ML logic fully decoupled from data persistence and business logic.

> For security reasons, this service is not exposed publicly. It can only be reached internally by `solargen-backend`, since both services run within the same private network.

## Tech Stack

- **FastAPI** — API framework
- **LightGBM** — gradient boosting model for hourly production forecasting
- **Open-Meteo** — live weather data source
- **pytest** — unit testing

## Model

The model predicts hourly capacity factor for each site from weather variables (temperature, shortwave and diffuse radiation, cloud cover, relative humidity) combined with cyclical time encodings (hour, month) and site capacity (kwp).

| Model    | R²    | MAE    | Training Period     | Validation              |
| -------- | ----- | ------ | ------------------- | ----------------------- |
| LightGBM | 0.8121 | 0.0647 | Jan 2020 – Apr 2022 | 5-fold cross-validation |

The full training process, including data exploration, feature engineering, model selection, and evaluation, is documented in [`model_development.ipynb`](https://nbviewer.org/github/wajrock/solargen/blob/develop/solargen-model/model/model_development.ipynb).

## Endpoints Overview

All endpoints require an API key, passed via the `X-API-Key` header.

| Method | Endpoint              | Description                                       |
| ------ | --------------------- | ------------------------------------------------- |
| `GET`  | `/model-infos`        | Model metadata and performance metrics            |
| `GET`  | `/installation`       | Metadata for all 21 sites                         |
| `GET`  | `/predictions`        | Hourly predictions for the current day, all sites |
| `GET`  | `/predictions/{date}` | Hourly predictions for a specific date, all sites |

## Key Architecture Components

```
app/
├── services/
│   ├── auth.py                  # API key verification
│   ├── installation_service.py  # Site metadata parsing
│   ├── model_service.py         # Model metadata formatting
│   ├── prediction_service.py    # Feature engineering and inference
│   └── weather_service.py       # Open-Meteo data fetching
└── models.py                    # Pydantic response schemas

model/
├── model_solar_prediction.pkl   # Trained LightGBM model
├── model_info.pkl               # Model metadata (metrics, training period)
└── model_development.ipynb      # Full model training and evaluation notebook

assets/                          # Source datasets (UNISOLAR, Open-Meteo) used for training and site metadata
```

## Testing

The test suite does not require any environment configuration.

```bash
pip install -r requirements.txt
pytest
```

Unit tests cover authentication, site metadata parsing (including empty-data edge cases), model info formatting, weather fetching, and prediction generation logic.

## CI/CD & Deployment

The service is deployed to [Northflank](https://northflank.com/) through a Docker-based CI/CD pipeline:

| Stage          | Description                                                                                                            |
| -------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Trigger        | A push touching `solargen-model/` triggers a build. Path-based rules keep each service's pipeline independent.         |
| Build & verify | Dependencies are installed and the full test suite runs during the build itself. A failing test blocks image creation. |
| Deploy         | On a successful build, the image is deployed automatically to Northflank's private network.                            |
